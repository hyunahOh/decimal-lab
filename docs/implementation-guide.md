# decimal-lab 구현 가이드

직접 구현하고 테스트로 결과를 확인하기 위한 작업 순서입니다. 완성 코드를 제시하기보다 각 단계의 입력, 내부 표현, 처리 순서와 완료 기준을 설명합니다.

아래는 구현 원리와 완료 기준입니다. 현재 구현은 `src/index.ts`에서 사용할 수 있으며, 파싱·출력·연산 테스트와 Node 벤치마크가 추가되어 있습니다.

## 1. 먼저 지킬 저장 규칙

값은 `coefficient × 10^(-scale)`입니다. `coefficient`는 항상 정수이고 `scale`은 소수점 위치를 나타내는 정수입니다.

| 입력 | coefficient | scale |
| --- | ---: | ---: |
| `12.34` | 1234 | 2 |
| `-0.0050` | -50 | 4 |
| `1.20` | 120 | 2 |
| `1e3` | 1 | -3 |
| `-0.00` | 0 | 2 |

- `small`: 정수값의 절댓값이 `10^15` 미만이며 `number`에 저장합니다.
- `big`: 그 외의 정수값을 `bigint`에 저장합니다. 안전한 16자리 정수도 현재 규칙에서는 big입니다.
- 숫자값이 0이면 부호를 없애되 scale은 유지합니다. `Object.is(coefficient, -0)`은 false여야 합니다.
- 앞의 0은 제거해도 되지만 뒤의 0은 자동으로 제거하지 않습니다.
- 지수와 scale은 안전한 정수여야 합니다.
- 입력 객체를 수정하지 않고 결과 객체를 반환하는 방식을 유지합니다.

`small`의 분류 기준과 `Number.MAX_SAFE_INTEGER`는 다른 개념입니다. 전자는 이 프로젝트의 저장 정책이고, 후자는 정수 계산의 정확도를 판단하는 범위입니다.

## 2. 일반 소수 파싱: parseDecimal

작업 파일: `src/parse.ts`

### 2-1. 입력 문법 검증

입력 전체가 다음 규칙에 맞는지 확인합니다.

1. 맨 앞에 `+` 또는 `-`가 하나 있을 수 있습니다.
2. 소수점은 최대 하나입니다.
3. 숫자가 적어도 하나 있어야 합니다.
4. 숫자는 ASCII `0`부터 `9`만 허용합니다.
5. 공백, 지수, 16진수, 숫자 구분자, NaN, Infinity는 거부합니다.

허용: `12`, `12.34`, `.5`, `12.`, `+.5`, `-0.00`.

거부: 빈 문자열, 공백, `+`, `.`, `1.2.3`, `0xff`, `1e3`, `1_000`.

정규식을 써도 되고 문자별로 검사해도 됩니다. 처음에는 읽기 쉬운 구현을 선택하세요. 정규식의 `$`만으로 검사하면 마지막 줄바꿈 직전에서 일치할 수 있으므로, 매치된 길이가 입력 전체 길이인지도 확인하거나 끝을 엄격하게 검사하세요. `1\n`과 `1\r\n`은 거부해야 합니다.

### 2-2. 부호와 소수 부분 추출

`-12.340`을 부호 `-`, 정수 부분 `12`, 소수 부분 `340`으로 나눕니다.

- 소수 부분 길이인 3을 scale로 정합니다.
- 정수 부분이 없는 `.5`는 정수 부분을 `0`으로 취급합니다.
- 소수 부분이 없는 `12` 또는 `12.`의 scale은 0입니다.

### 2-3. 정수 문자열 만들기

정수 부분과 소수 부분을 이어 붙이고 앞의 0만 제거합니다.

`000.0050` → `0000050` → `50`, scale은 계속 4입니다.

모든 자리가 0이면 빈 문자열 대신 `0`을 사용합니다. 0에는 음수 부호를 적용하지 않습니다.

### 2-4. 저장 방식 결정

부호와 앞의 0을 제외한 정수 문자열이 15자리 이하면 Number로 변환합니다. 그보다 길면 문자열에서 바로 BigInt로 변환합니다.

큰 값을 `Number`로 먼저 읽고 `BigInt`로 바꾸면 이미 잃은 정확도를 복원할 수 없습니다. `parseFloat`는 일부 문자열만 읽고 나머지를 무시할 수 있으므로 입력 검증 수단으로 사용하지 않습니다.

### 완료 기준

- 기존 `parseDecimal`의 정상 입력 테스트 11개가 통과합니다.
- 잘못된 입력 테스트 13개가 통과합니다.
- `999999999999999`는 small, `1000000000000000`은 big입니다.
- `-0.00`의 coefficient는 양수 0이며 scale은 2입니다.
- 추가로 마지막 줄바꿈, 음수 큰 정수, 앞에 0이 많은 입력도 검사합니다.

## 3. 지수 파싱: parseScientific

### 처리 순서

1. `e` 또는 `E`를 기준으로 본문과 지수를 나눕니다.
2. 지수가 없으면 `parseDecimal` 결과를 반환합니다.
3. 지수 구분자가 두 개 이상이면 거부합니다.
4. 본문은 `parseDecimal`로 처리합니다.
5. 지수는 선택적인 부호와 하나 이상의 숫자로만 구성돼야 합니다.
6. 지수를 Number로 변환하고 `Number.isSafeInteger`로 확인합니다.
7. `최종 scale = 본문의 scale - 지수`를 계산합니다.
8. 최종 scale도 안전한 정수인지 확인하고 결과를 만듭니다.

지수에는 `parseInt`만 사용하지 마세요. `2x`나 `1.5` 같은 잘못된 입력을 일부만 읽어 허용할 수 있습니다. 일반 소수와 마찬가지로 지수 문자열 끝의 줄바꿈도 거부해야 합니다.

| 입력 | 본문 coefficient | 본문 scale | 지수 | 최종 scale |
| --- | ---: | ---: | ---: | ---: |
| `1.23e4` | 123 | 2 | 4 | -2 |
| `1.23e-4` | 123 | 2 | -4 | 6 |
| `1.20E+1` | 120 | 2 | 1 | 1 |
| `1e100` | 1 | 0 | 100 | -100 |
| `-0.00e3` | 0 | 2 | 3 | -1 |

지수만큼 실제 0을 추가하지 않습니다. `1e100`도 coefficient가 1인 small로 저장할 수 있습니다.

### 완료 기준

- 기존 `parseScientific` 테스트 13개가 통과합니다.
- `1e`, `1e+`, `1e2e3`, `1e1.5`, `e3`를 거부합니다.
- 지수 범위 초과뿐 아니라 최종 scale 범위 초과도 거부합니다.
- 전체 파싱 테스트 37개와 타입 검사가 통과합니다.

정상 입력이 정확한 객체를 반환하는지와 오류 입력이 거부되는지를 함께 확인하세요.

## 4. 결과를 눈으로 확인하는 문자열 출력

다음 단계로 `toPlainString(value)`를 구현하면 연산을 디버깅하기 쉽습니다. 파일은 `src/format.ts`처럼 분리할 수 있습니다. 아직 기존 테스트에 없는 기능이므로 아래 기대값부터 테스트로 추가합니다.

1. coefficient의 부호를 분리하고 절댓값을 문자열로 바꿉니다.
2. scale이 0이면 정수 문자열을 반환합니다.
3. scale이 음수이면 뒤에 `-scale`개의 0을 붙입니다.
4. scale이 양수이면 오른쪽에서 scale자리 앞에 소수점을 넣습니다.
5. 숫자 문자열이 짧으면 왼쪽에 0을 채워 `0.0050`처럼 만듭니다.
6. 음수일 때만 맨 앞에 부호를 붙입니다.

예: `(1234, 2)` → `12.34`, `(50, 4)` → `0.0050`, `(1, -3)` → `1000`.

0도 별도로 처리하세요. `(0, 2)`는 `0.00`, `(0, -3)`은 이 함수의 출력 정책상 `0`으로 정할 수 있습니다. 음수 scale까지 보존하는 직렬화가 필요하면 지수 표기를 지원하는 별도 함수를 설계합니다.

지수만 저장할 때는 작아도 출력은 매우 길 수 있습니다. 문자열을 만들기 전에 최대 출력 길이를 제한하세요. 큰 음수 scale로 `repeat()`를 바로 호출하지 않습니다.

## 5. 저장 타입을 결정하는 공통 함수

연산을 추가하기 전에 결과를 일관되게 만드는 내부 함수를 설계합니다.

- 정수값이 small 범위에 들어가면 small로 반환합니다.
- 범위를 벗어나면 big으로 반환합니다.
- bigint 결과가 작아진 경우 small로 줄일지는 정책을 통일합니다. 처음에는 줄이는 쪽으로 정하면 파서와 결과가 일관됩니다.
- 0의 부호를 정규화하고 scale을 검사합니다.

처음에는 정답을 내는 구현을 만들고, 이 함수나 변환이 병목인지 측정한 뒤 최적화하세요.

## 6. 덧셈과 뺄셈

권장 순서: `add`를 먼저 만들고 `subtract`는 두 번째 인수의 정수값 부호를 바꿔 add를 재사용합니다.

### scale 맞추기

두 scale 중 큰 값을 결과 scale로 선택합니다. 각 정수값에 `10^(결과 scale - 원래 scale)`을 곱합니다.

`1.2 + 0.03`:

- 첫 번째 값: coefficient=12, scale=1.
- 두 번째 값: coefficient=3, scale=2.
- 결과 scale은 2.
- 첫 번째 coefficient를 120으로 맞춥니다.
- `120 + 3 = 123`, scale=2이므로 결과는 `1.23`입니다.

### 처음에는 BigInt로 정확성을 확인

양쪽 coefficient를 BigInt로 바꿔 정렬하고 더하면 기준 구현을 만들기 쉽습니다. 결과를 공통 함수로 분류합니다. 이 단계는 빠른 구현이 아니라 정확한 기준 구현입니다.

### 이후 small 전용 경로 추가

둘 다 small일 때 정렬에 필요한 정수 곱셈과 합이 정확한 범위임을 증명할 수 있으면 Number 경로를 사용합니다. 결과가 small 범위를 벗어나면 정확한 정수값을 BigInt로 옮겨 반환합니다.

정확도를 잃을 수 있는 계산을 먼저 수행한 뒤 그 값을 BigInt로 바꾸면 안 됩니다. Number 경로가 안전하지 않으면 원래 입력의 정확한 정수값으로 돌아가 BigInt 연산을 수행하세요.

scale 차이가 지나치게 크면 막대한 정수를 만들 수 있습니다. 지수와 scale이 안전한 정수라는 사실만으로 메모리 사용량까지 안전한 것은 아닙니다. 정렬 자릿수 한도를 별도로 정하세요. scale 차이 계산 자체의 안전한 정수 여부도 확인합니다.

### 추가할 테스트

- `0.1 + 0.2 = 0.3`.
- `1.20 + 0.03 = 1.23`.
- `1.20 + (-1.20)`의 결과는 coefficient=0, scale=2.
- small 범위를 넘어가는 덧셈과 큰 수의 상쇄.
- 서로 다른 부호, 서로 다른 scale, 음수 scale.
- 입력 객체가 연산 후 변경되지 않는지 확인.

## 7. 곱셈

`결과 coefficient = a.coefficient × b.coefficient`.

`결과 scale = a.scale + b.scale`.

예: `1.20 × 0.3` → `120 × 3 = 360`, scale은 `2 + 1 = 3`, 결과 `0.360`.

먼저 BigInt 기준 구현을 만든 뒤 small 경로를 추가합니다. 곱셈은 입력이 small이어도 결과가 안전한 정수 범위를 쉽게 넘습니다. Number 경로를 허용할 보수적인 사전 조건을 정하고 그 조건을 경계값 테스트로 검증하세요. 안전하지 않으면 원래 입력을 BigInt로 변환해 곱합니다.

결과 scale 합도 범위를 확인하고, 0·음수·small에서 big으로 커지는 경우를 검사합니다.

## 8. 반올림과 setScale

처음에는 소수점 아래 자릿수를 지정하는 `setScale(value, targetScale, mode)`부터 만듭니다. 유효 자릿수 precision과 소수 자릿수 scale을 혼동하지 않습니다.

### scale을 늘릴 때

정수값에 `10^(targetScale - scale)`을 곱합니다. 숫자값은 같고 표현 자릿수만 늘어납니다.

예: `1.2` → scale=3이면 coefficient=1200, 결과 `1.200`.

### scale을 줄일 때

`divisor = 10^(scale - targetScale)`로 두고 정수 몫과 나머지를 구합니다. 나머지가 0이면 정확하므로 반올림하지 않습니다.

| 모드 | 나머지가 있을 때 처리 |
| --- | --- |
| DOWN | 0 방향으로 버림 |
| UP | 0에서 멀어지는 방향으로 한 단위 이동 |
| CEILING | 양수일 때만 몫을 1 증가 |
| FLOOR | 음수일 때만 몫을 1 감소 |
| HALF_UP | `2 × abs(나머지) >= divisor`면 0에서 멀어지게 이동 |
| HALF_DOWN | `2 × abs(나머지) > divisor`일 때 이동 |
| HALF_EVEN | 절반 초과면 이동, 정확히 절반이면 몫이 홀수일 때 이동 |
| UNNECESSARY | 나머지가 있으면 오류 |

BigInt 나눗셈은 0 방향으로 자릅니다. DOWN은 FLOOR와 다릅니다. 음수 반올림에서 부호 처리를 특히 확인하세요.

`2.5`, `3.5`, `-2.5`, `-3.5`를 정수로 만드는 테스트와 `9.995`를 두 자리로 만드는 올림 전파 테스트를 추가합니다. 결과가 0이면 음수 0을 남기지 않습니다.

## 9. 나눗셈

처음에는 결과 scale과 반올림 모드를 명시적으로 받는 API를 만듭니다. 무한소수의 정확한 나눗셈이나 유효 자릿수 기반 API는 뒤로 미룹니다.

a를 `(A, sa)`, b를 `(B, sb)`, 원하는 결과 scale을 `s`라고 하면 결과 정수값의 반올림 전 값은 다음과 같습니다.

`(A / B) × 10^(s + sb - sa)`.

1. 먼저 B가 0인지 검사합니다.
2. `k = s + sb - sa`를 계산합니다. scale 계산 중간값도 안전한 정수인지 검사하거나 BigInt로 계산한 뒤 허용 범위를 검증합니다.
3. k가 0 이상이면 분자 A에 `10^k`를 곱합니다.
4. k가 음수이면 분모 B에 `10^(-k)`를 곱합니다.
5. 분모는 양수로 정규화하고 분자에 전체 부호를 둡니다.
6. 정수 몫과 나머지를 계산합니다.
7. 앞 단계의 반올림 규칙으로 몫을 조정합니다.
8. 결과 coefficient와 지정한 scale을 반환합니다.

예: `1 / 8`, 결과 scale=2이면 `100 / 8`의 몫은 12, 나머지는 4입니다. HALF_UP에서는 13으로 조정해서 `0.13`이 됩니다.

검사할 값: `1/2`, `1/3`, `1/8`, 음수 피연산자, 음수 결과 scale, 0으로 나누기, 나머지 없는 나눗셈. 10의 거듭제곱을 만들기 전 자릿수 한도를 검사합니다.

## 10. 성능 최적화 순서

1. BigInt 기준 구현과 동작 테스트를 먼저 완성합니다.
2. 별도의 무작위 입력으로 small 경로 결과를 BigInt 기준 결과와 비교합니다.
3. 생성만, 연산만, 문자열 출력만 따로 측정합니다.
4. 문자열 입력 → 여러 연산 → 최종 출력의 전체 흐름도 측정합니다.
5. 실제 사용 환경의 데스크톱과 모바일 브라우저에서 측정합니다.
6. 변환 비용과 객체 생성·GC 비용을 포함해 이득이 있는 최적화만 남깁니다.

small은 처음 생성할 때부터 정수 Number로 유지하고, 범위를 넘을 때만 BigInt로 전환하는 방향입니다. 메서드마다 정수와 자릿수 배열을 오가면 변환 비용이 추가됩니다.

속도 수치를 비교할 때 입력 자릿수, 소수 자릿수, 반올림 규칙, 문자열 출력 포함 여부가 같아야 합니다. 이미 만든 객체의 연산과 문자열에서 매번 생성하는 연산은 따로 측정합니다. 워밍업과 반복 측정으로 변동도 확인합니다.
