# decimal-lab

소수 연산을 직접 구현하며 정확도와 성능을 학습합니다.
정수 coefficient와 scale로 값을 저장하며 파싱, 문자열 출력, 사칙연산과 반올림을 지원합니다.

## 시작

Node.js 24 권장 (최소 22).

```sh
npm install
npm run typecheck
npm test
npm run test:watch
npm run bench
npm run bench:compare
npm run bench:three -- --minutes 10 --rounds 5
npm run test:upstream
```

`test:upstream`은 big.js v7.0.1의 원본 테스트를 현재 구현에 실행하고 `reports/upstream-tests.json`에 결과를 저장합니다.
`node scripts/test-upstream.mjs --reference`로 같은 테스트가 원본 big.js에서 통과하는지 확인할 수 있습니다.
검사 내용은 수정하지 않으며, 오류 메시지와 내부 속성 호환성 검사도 포함하므로 현재는 실패 종료합니다.

`bench:compare`는 big.js 7.0.1과 공개 API 성능을 비교합니다. small 입력, 15/16자리 경계, 30·100·1,000자리 입력을
각각 32쌍 사용하고, 양쪽 모두 `DP=20`, `RM=HALF_EVEN`으로 설정합니다. 생성·각 연산·출력과 생성부터 출력까지의
전체 흐름을 구분하며, 측정 전에 모든 입력의 결과가 같은지 확인합니다.
각 항목은 20ms 워밍업 후 최소 75ms 측정하고, 독립 Node 프로세스 5회의 중앙값과 최소·최대값을 기록합니다.
결과는 `reports/benchmark-comparison.json`과 `.csv`, 회차별 원자료는 `reports/benchmark-run-*.json`에 저장합니다.
`speedup`은 big.js 시간 ÷ decimal-lab 시간으로 1보다 크면 decimal-lab이 빠릅니다.
객체 생성과 자연 발생 GC 비용은 포함하며 브라우저 성능과 메모리 사용량은 별도로 측정해야 합니다.

`bench:three`는 decimal-lab, big.js, decimal.js를 비교합니다. 기본값은 라이브러리마다 실제 측정 시간 약 10분,
독립 프로세스 5회이며, 세 라이브러리를 번갈아 측정하므로 총 약 30분에 준비·워밍업 시간이 추가됩니다.
small 유지, small에서 big으로 승격, 경계값, 30·100·1,000자리 등을 포함한 112개 항목의 입력별 결과 일치를 먼저 확인하고
`reports/three-way/`에 회차별 원자료와 최종 JSON·CSV를 저장합니다. 각 연산의 실제 입력·결과가 small인지 big인지도 보고서에 기록합니다.
시간은 112개 항목에 균등 배분하며, 각 항목은 입력 32쌍을 모두 처리하는 배치 단위라 목표 시간보다 조금 길어질 수 있습니다.

decimal.js는 소수 자릿수 대신 유효 자릿수로 연산을 반올림하므로 연산별 독립 생성자를 사용합니다.
덧셈·뺄셈·곱셈·세제곱은 모든 결과 자릿수를 보존할 정밀도를 설정하고, 나눗셈·제곱근·전체 흐름은
필요한 정수 자릿수 + 소수 20자리 + 여유 10자리로 계산한 후 `toDP(20)`을 적용합니다.
이 변환 비용도 측정에 포함합니다. 이는 현재 입력의 출력 결과를 맞추는 비교이며 기본 설정끼리의 비교가 아닙니다.
그룹별 실제 정밀도, 라이브러리 버전, 소스 해시와 실제 측정 시간은 최종 보고서에 기록됩니다.

30자리 이내에 집중할 때는 `--groups small-6-digit,small,small-promotion,boundary,30-digit`를 추가합니다.
`small-6-digit`는 덧셈·곱셈 결과도 small인 입력이며, `small-promotion`은 두 입력이 small이고 덧셈·곱셈 결과가 big인 입력입니다.
나눗셈·제곱근처럼 결과 정밀도에 따라 저장 타입이 달라지는 연산은 실제 타입별 개수를 확인해야 합니다.
`--minutes`는 각 구현의 누적 측정 시간입니다.
`--baseline /path/to/before/src`를 지정하면 변경 전 TypeScript 소스도 같은 프로세스와 입력으로 비교합니다.
`--output reports/custom-comparison`으로 기존 보고서를 덮어쓰지 않고 결과를 저장할 수 있습니다.

현재 구현은 30자리 이내의 변환·할당 비용을 줄이도록 최적화했습니다. 이미 만든 Big 인수는 복제하지 않고 읽으며,
복사 생성자는 정규화된 내부 값을 공유합니다. 연산은 계속 새 결과 객체를 반환합니다.
small 정규화와 안전한 덧셈·곱셈은 Number로 처리하고, 범위를 넘으면 원래의 정확한 정수값으로 BigInt 연산을 수행합니다.
자주 쓰는 10의 거듭제곱을 캐시하고, 생성·비교·출력에서 반복적인 문자열 변환과 BigInt 변환을 줄였습니다.

`src/index.ts`의 기본 내보내기는 big.js 방식의 `Big` 생성자입니다. `new` 없이도 호출할 수 있습니다.

```ts
import Big from "./src/index";

Big.DP = 20;
Big.RM = Big.roundHalfUp;

Big("0.1").plus("0.2").toString(); // "0.3"
new Big("1.20").times(3).toFixed(2); // "3.60"
Big("1").div("8").toFixed(2); // "0.13"
Big("2.5").round(0, Big.roundHalfEven).toString(); // "2"
Big("2.25").sqrt().toString(); // "1.5"
Big("2").pow(-3).toString(); // "0.125"
Big("1").mod("0.3").toString(); // "0.1"
Big("123.456").prec(4).toString(); // "123.5"
Big("12.3").toPrecision(5); // "12.300"
Big("12.3").toExponential(3); // "1.230e+1"
```

지원 API:

- `plus` / `add`, `minus` / `sub`, `times` / `mul`, `div`, `mod`, `pow`, `sqrt`
- `round`, `prec`, `abs`, `neg`
- `cmp`, `eq`, `gt`, `gte`, `lt`, `lte`
- `toString`, `toFixed`, `toPrecision`, `toExponential`, `toJSON`, `toNumber`, `valueOf`
- 설정 `DP`, `RM`, `NE`, `PE`, `strict` 및 반올림 상수 4개

연산은 새 객체를 반환합니다. 입력은 문자열, number, bigint, 같은 구현의 Big 객체를 받습니다.
기본 설정은 `DP=20`, `RM=1`, `NE=-7`, `PE=21`, `strict=false`입니다.
`Big()`는 독립적인 기본 설정을 가진 생성자를 반환합니다. `strict=true`이면 number 입력과 `valueOf`를 거부하고,
`toNumber`에서 값 손실을 검사합니다.

호환 API는 끝 0을 제거합니다. `Big("1.20").toString()`은 `"1.2"`이며, 자릿수 지정은 `toFixed(2)`로 합니다.
음수 0은 내부 부호를 보존하며 `toString()`은 `"0"`, `valueOf()`는 `"-0"`을 반환합니다.
문자열 앞의 `+`는 받지 않습니다.

`sqrt()`와 음수 지수의 `pow(n)`은 `DP`와 `RM`을 사용합니다. 양수 지수 거듭제곱과 `mod`는 정확한 값을 계산합니다.
`pow`의 지수 범위는 -1,000,000부터 1,000,000까지의 정수입니다. `prec(sd, rm)`은 최대 유효 자릿수로 반올림하고,
`toPrecision(sd, rm)`은 지정한 유효 자릿수를 0으로 채워 출력합니다. `toExponential(dp, rm)`은 지수 표기로 출력합니다.

호환 목표는 big.js의 일반 사용 API입니다. 내부 저장 표현인 `c`(자릿수 배열), `e`(지수), `s`(부호)의
직접 접근·변경과 해당 속성 검사는 호환 범위에서 제외합니다. 이 프로젝트는 coefficient·scale 구조를 사용하므로,
이 속성에 의존하는 코드까지 포함한 완전한 대체를 보장하지 않습니다.
음수 0은 내부 속성 대신 `valueOf()`와 `toNumber()`의 공개 동작으로 검증합니다.
원본 테스트의 `c/e/s` 검사 실패는 위 호환 범위에 따른 차이로 구분합니다.
오류 메시지 문자열은 일치시키지 않습니다.
기존 출력·연산 메모리 한도는 적용되므로 큰 자릿수 요청은 big.js와 달리 `RangeError`가 날 수 있습니다.
모든 문자열 출력에 100,000자 제한을 적용하며, 거듭제곱 중간 coefficient도 100,000자리로 제한합니다.
제곱근 계산에서도 정수로 확장하는 10의 거듭제곱은 최대 100,000입니다.

기존 함수형 API는 scale과 끝 0을 보존하며 계속 사용할 수 있습니다.

```ts
import { parseScientific, add, divide, setScale, toPlainString } from "./src/index";

const a = parseScientific("1.20");
const b = parseScientific("0.03");
toPlainString(add(a, b)); // "1.23"
toPlainString(divide(a, b, 2, "HALF_EVEN")); // "40.00"
toPlainString(setScale(a, 3, "UNNECESSARY")); // "1.200"
```

`subtract(a, b)`, `multiply(a, b)`도 새 결과 객체를 반환합니다.
`setScale(value, scale, mode)`와 `divide(a, b, scale, mode)`는 결과 scale과 반올림 모드를 명시해야 합니다.
모드는 `DOWN`, `UP`, `CEILING`, `FLOOR`, `HALF_UP`, `HALF_DOWN`, `HALF_EVEN`, `UNNECESSARY`입니다.
`UNNECESSARY`에서 나머지가 생기거나 0으로 나누면 오류를 던집니다.

## 구현 순서

1. `parseDecimal`: 부호 → 정수/소수 부분 → 소수 길이로 scale 결정.
2. 앞의 0만 제거. 모든 숫자가 0이면 coefficient는 0, scale은 유지.
3. 정수값이 15자리 이하면 number, 초과하면 문자열에서 바로 BigInt로 변환.
4. `parseScientific`: e/E 분리 → 지수 검사 → scale에서 지수 빼기.
5. 덧셈: scale 정렬과 안전한 정수 범위 검사를 먼저 설계.
6. 반올림 → 곱셈 → 나눗셈 → 실제 입력으로 벤치마크.

## 이번 단계의 규칙

- 값 = coefficient × 10^(-scale).
- small 기준은 보수적으로 15자리 이하. 안전한 16자리 정수도 우선 big입니다.
- `1.20`은 coefficient=120, scale=2로 끝 0을 보존합니다.
- `-0.00`은 coefficient=0, scale=2로 저장합니다.
- 공백을 자동으로 제거하지 않습니다.
- 지수와 scale은 `Number.isSafeInteger` 범위여야 합니다.
- 출력은 부호와 소수점을 포함해 최대 100,000자입니다. `toPlainString(value, maxLength)`로 더 낮출 수 있습니다.
- 정렬·scale 변경·나눗셈에서 생성하는 10의 거듭제곱은 최대 100,000자리까지 허용합니다. 초과하면 `RangeError`를 던집니다.
- 입력 길이와 기존 coefficient 자릿수에는 별도의 한도를 두지 않습니다.
- 연산 중간값도 검사해야 합니다. 입력이 small이라고 결과까지 정확하진 않습니다.

## 연산별 성능 측정 결과

Apple M2 · Node.js 24.14.0 · big.js 7.0.1 · decimal.js 10.6.0에서 측정했습니다.
단위는 **μs/회**이며 작을수록 빠릅니다. 독립 프로세스 5회의 중앙값이고, 각 행의 최솟값을 굵게 표시했습니다.

나눗셈·제곱근은 소수 20자리, 반올림은 HALF_EVEN이며 decimal.js의 같은 출력 보정 비용도 포함합니다.
미리 생성한 객체로 개별 연산을 측정하며, 생성과 마지막 전체 흐름 항목만 문자열 입력을 포함합니다.

small 유지·승격은 덧셈과 곱셈 결과의 실제 저장 타입으로 확인했습니다. 나눗셈 등 다른 연산은 결과 타입이 달라질 수 있습니다.
